# AGENTS.md — BiedaMT

Guide for coding agents (Claude Code, Codex, opencode, ...) working in this codebase.

## What this is

Single-file desktop translator app (Windows, Python 3.10+): llama-server subprocess + TMX memory RAG (ChromaDB) + global hotkey clipboard translation + pystray tray icon + FastAPI side API.

## Commands

- Run the full app: `python main.py` (needs `config.yaml`, llama-server and the model; see Testing for running without the full stack)
- Preview the Settings window standalone: `python settings_gui.py` (fake save/restart callbacks, never touches `config.yaml`)
- Import/syntax check without the full stack: `python -c "import ast; ast.parse(open('main.py', encoding='utf-8').read())"`
- There is no test suite; "Testing without the full stack" below lists what can be exercised where.

## Layout

- `main.py` — everything: config load, replacements, translation pipeline, hotkey action, tray menu, llama-server lifecycle, FastAPI app, `main()`
- `settings_gui.py` — Settings window (tkinter in its own thread): field spec (`FIELD_SECTIONS`, the GUI's view of every config knob incl. restart badges), opened from the `Settings` tray item
- `rag_engine.py` — `TMXTranslatorRAG` (one collection per TMX) + `RAGManager` (load/reload/delete + `resolve_engines`/`search_selected` for the tray memory selection)
- `config.yaml` — **single source of truth**. No hardcoded paths, ports, model names or tunables in code. If you need a new knob, add it here and read via `CONFIG[...]`. Note: `config.yaml` is git-ignored (owner's private local paths); `config.example.yaml` is the tracked template — when adding a new knob, add it to both.
- `replacements.py` — user-editable regex replacements applied before ("source") and after ("target") translation
- `memories/*.tmx` — TMX memories; filename (sans extension) = memory name
- `chroma/` — ChromaDB persistent store (created at runtime, never commit/edit)
- `state.json` — session state (remembered tray memory selection); path from `ui.state_file`, created at runtime, git-ignored
- `assets/` — tray icons

## Architecture invariants — do not break

1. **pystray must run on the main thread.** `icon.run()` is the last call of `main()`; uvicorn runs in a daemon thread. Windows message pump requirement — inverting this produces a silent app (uvicorn up, no tray).
2. **pystray action signatures are validated.** Menu actions must be callables accepting `(icon, item)`. Use `functools.partial(fn, arg)` where `fn` takes the bound arg first plus `*args`, or plain `fn(icon, item)`. A lambda with a third default param raises `ValueError` from `pystray._base._assert_action` at menu build time.
3. **Rebuild the menu after any state change** (memory selection, hotkey toggle, language, memory list changes) via `rebuild_menu()`.
4. **Hotkey pipeline order** (`action()`): guard `hotkey_active` → busy icon → snapshot clipboard → `keyboard.send('ctrl+c')` → poll until clipboard content changes (25 ms interval, 0.5 s cap; replaced a fixed sleep that was too short on slow apps) → `pyperclip.paste()` → source replacements → translate → target replacements → `pyperclip.copy` → `delete` → `ctrl+v` → active icon.
5. **Translation pipeline** (`translate_with_rag`): exact TM lookup (sqlite `where` on metadata — direct return, no LLM) → RAG search (`search_selected` over the tray-selected memories) → `filter_references` (distance threshold + sort + dedupe + truncation, knobs in `rag.*`) → fuzzy-TM shortcut (best hit within `rag.fuzzy_match_distance` returns directly, no LLM) → glossary lookup (`find_terms`: short TMX segments act as a termbase; hits are injected by `build_rag_prompt` as a mandatory "Terminy" block that overrides the references) → `build_rag_prompt` (plain-text, direction-aware prompt with EN/PL references; wording = `prompt.*` templates in `config.yaml`, live-reloadable via the `Reload prompt` tray item — `DEFAULT_PROMPT` in main.py is only a fallback) → `llm_chat_request` (lokalny llama-server `/v1/chat/completions` albo zewnętrzne API — patrz niezmiennik 12). It does NOT use `build_rag_chatmessage` / the `[USER_PROMPT]`/`[REFERENCES]` protocol — that protocol lives only in the archived `/v1/chat/completions_old` endpoint. The live `POST /v1/chat/completions` ignores the client's system/user prompts entirely: it extracts just the `[SOURCE]` section after `\n[USER_PROMPT]\n` (real Trados payload: `[SOURCE]` alone on a line; the text ends at the next `[SECTION]` tag line, e.g. `[TARGET]`; no `[SOURCE]` = fall back to the whole remainder, fallback: last user message) and calls `translate_with_rag` with the tray-selected memories and tray direction, so API translations are identical to the hotkey path (glossary, prompt templates, exact/fuzzy match). Request `temperature`, `max_tokens` and `rag_memory` are ignored; only `model` is echoed back.
6. **RAG search context**: `translate_with_rag` takes `memories: Optional[Collection[str]]` = the tray checkbox selection (`selected_memories` global): `None` = every loaded memory (`search_selected` embeds the query once and pulls `rag.search_all_per_memory` from each), a name set = only those, an empty set = no memory at all (plain LLM). Tray menu = checkboxes (`toggle_memory`, pystray `checked`); the "everything checked" state is normalized back to `None` so memories loaded later are included automatically. One engine selected = `rag.search_results` from it.
7. **The memory selection is session state, persisted in `ui.state_file`** (JSON, runtime-created, git-ignored; written atomically via `.tmp` + `os.replace`). `_initial_selection()` runs at import: last saved selection wins (`null` = all, `[]` = none, list = those memories), otherwise `translation.default_memory` (`null` = **no** memory — a fresh start selects nothing, by owner's decision). Written on `toggle_memory`, on GUI `default_memory` change, and when `ui.state_file` moves (so a changed path immediately holds the current selection). Stale names (memory deleted via API/GUI) are ignored by `resolve_engines` and dropped from the set by `_prune_selected_memories()` (called in `main()` right after RAG init) and by the next `toggle_memory`.
8. **llama-server lifecycle**: started in `start_llama()` (falls back to `llama-server` on PATH if configured path missing; readiness = polling `/health` up to `llama.startup_timeout`, then a background warmup request), stopped via `atexit` + `stop_llama()` on Quit. Config: `llama.server_path`, `llama.model_path`, `llama.args` (port lives in both `llama.port` and `llama.args` — the Settings GUI auto-syncs them on save; args are stored as one string — the GUI format — or a YAML list; `start_llama` flattens both to argv tokens via `split_args_string`), `llama.request_timeout`. **External LLM mode** (`external.enabled`, niezmiennik 12): `main()` nie uruchamia wtedy llama-servera, a `save_settings()` przy przełączeniu zatrzymuje lokalny serwer (`stop_llama()`), żeby nie trzymać modelu w VRAM; powrót do trybu lokalnego startuje go w tle (`start_llama_background()`, ten sam `_llama_restart_lock` co `restart_llama_async`, błędy tylko w logu). W trybie zewnętrznym zmiany kluczy `llama.*` są zapisywane, ale bez przycisku „Restart LLM” (nota w GUI: zadziałają po powrocie do lokalnego).
9. **No filesystem watcher for memories — by design.** The owner updates TMX files by copying large exports into `memories/`; polling could catch a half-written file. Loading is explicit: `Refresh memories` (pick up NEW tmx files; existing ones re-attach from the Chroma cache) and `Reload memory → <name>` (force re-import of an updated TMX into Chroma). Do not reintroduce automatic polling.
10. **RAG embeddings are computed manually** (sentence-transformers directly, NOT chromadb's embedding functions): documents embedded with the `passage: ` prefix, queries with `query: ` (e5 model requirement), `normalize_embeddings=True`, collections created with `hnsw:space: cosine`. Each collection carries an `embedding` marker in its metadata (`EMBEDDING_MARKER` + model name via `embedding_marker()` in rag_engine.py) — when embedding logic or the model changes, bump the marker: old collections are detected and re-imported from TMX on next start (collections marked with the bare legacy marker are still accepted for `LEGACY_E5_MODEL`). `search_selected` embeds the query once and reuses it across all selected memories. Lazy RAG costs (first `model.encode`, per-collection HNSW index load, glossary metadata scan) are preheated on purpose: `RAGManager.warmup()` runs in the background thread at startup (`warmup_llama`) and after `Refresh memories`, and `reload_memory` warms the reloaded engine via `_warmup_engine` — new engines have empty `_terms_cache`, so cover any new lazy cost in those spots.
11. **Settings GUI: thread split + restart policy.** The window runs Tk in a daemon thread spawned by `settings_gui.open_settings()` — never touch Tk objects from other threads; cross-thread traffic goes through `SettingsWindow._ui_queue` (polled in the Tk loop) and the module-level `_focus_request` event. Restart-required metadata lives in `settings_gui` (`Field.restart` = `""`/`"llama"`/`"app"`, exposed as `RESTART_LLAMA_KEYS`/`RESTART_APP_KEYS`); the live-apply policy (merge into `CONFIG`, hotkey rebind, prompt reload, tray icon refresh, `rebuild_menu()`) lives in `main.save_settings()` — keep that split (spec/labels in settings_gui, behavior in main). When adding a config knob: add it to `FIELD_SECTIONS` *and* to both `config.yaml` and `config.example.yaml`. `start_llama()` raises `LlamaStartError` instead of `sys.exit` so the GUI's "Restart LLM" button can fail gracefully — only `main()` converts it to process exit at startup. GUI saves go through `save_config_values()` (ruamel round-trip preserves comments; creates `config.yaml.bak`). `restart_llama_async()` invokes its callbacks on a worker thread — the receiver must marshal them to its own UI thread (the Tk window does this via `_ui_queue`). Pola `kind="secret"` (np. `external.api_key`) renderują się jako `Entry(show="•")` — walidacja/harvest idzie tą samą ścieżką co `str`.
12. **Two LLM backends, one pipeline.** `llm_chat_request(prompt)` in main.py is the only place that talks to an LLM, used by `translate_with_rag` and `warmup_llama`. Bez `external.enabled` idzie do lokalnego `http://127.0.0.1:{llama.port}/v1/chat/completions` z `cache_prompt` i bez `model`; z `external.enabled` — do `external.url` (normalizacja `external_chat_url()`: pełny endpoint zostaje, baza z wersją API dostaje `/chat/completions`, samo `http(s)://host` dostaje `/v1/chat/completions`) z polami `model` i `Authorization: Bearer {api_key}` (bez `cache_prompt`, bo zewnętrzne API odrzucają nieznane pola). `temperature` z `translation.*` w obu trybach, `max_tokens` z `external.max_tokens` (puste = `translation.max_tokens`), timeout z `external.timeout` albo `llama.request_timeout`. **`external.extra_body`** (mapa YAML albo tekst YAML) jest doklejana do payloadu zewnętrznego — tym podaje się pola specyficzne dla dostawcy (wyłączenie reasoningu: `reasoning_effort: none`, `thinking: {type: disabled}`, `reasoning: {enabled: false}`, `chat_template_kwargs: {enable_thinking: false}`); klucze `messages`/`model`/`stream` są odrzucane, a obecność `max_completion_tokens` usuwa `max_tokens` (OpenAI modele rozumujące). Gdy provider odpowie 400 z treścią o nieznanym polu, `llm_chat_request` ponawia raz bez `extra_body` (nie zabija tłumaczenia). Każda odpowiedź loguje `finish_reason` i usage (w tym `reasoning_tokens`); pusta treść z `finish_reason=length` daje czytelny `RuntimeError` zamiast cichego pustego tłumaczenia (u owner’a model `deepseek-v4.1-flash:free` przez bramkę palił cały limit 1024 na reasoning i bramka zwracała 502 — `reasoning_effort: none` rozwiązało problem). Tryb czytany przy każdym zapytaniu (`external_llm_enabled()`), więc przełączenie w GUI działa bez restartu. Warmup LLM jest pomijany w trybie zewnętrznym (płatne zapytanie). `/health` nie odpytuje zewnętrznego API — raportuje `llm_backend`/`llm_model`. Archiwalny `/v1/chat/completions_old` zostaje lokalny (pass-through do llama-servera).

## Platform gotchas (Windows)

- `keyboard` lib: global hotkeys may require running as admin depending on the target window; `` ` `` (backtick) is fine as a hotkey string.
- `windll.shcore.SetProcessDpiAwareness(1)` and AppUserModelID are wrapped in try/except — keep them non-fatal.
- Source files use CRLF. `git`/editors may normalize; Python doesn't care, but keep diffs clean.
- Paths in `config.yaml` use Windows-style strings (`d:\\Tools\\...`) — in YAML double-quoted strings backslash escapes apply; when adding paths prefer forward slashes or single quotes.

## Conventions

- User-facing strings, comments, log prints: Polish (project owner's language). Code identifiers: English. README.md is owner-facing too — keep it in Polish.
- Exception: tray menu labels are English-only (owner's decision) — e.g. `Memory`, `Reload memory`, `(no memories)`. The `Memory` value line reads `All` when every memory is checked and `(none)` when none is. Keep new menu items consistent with that.
- Emoji log prefixes are the established debug style (`🔥 hotkey`, `📋 clipboard`, `📖 RAG`, `🤖 llama`, `❌ error`, `✅ done`). Keep new logs consistent.
- Debug prints in `action()`/`translate_with_rag` are intentional (active development). Don't remove wholesale; gate behind a `debug` config flag if noise becomes a problem.

## Testing without the full stack

- If llama-server/GPU is not available in the environment (e.g. a Linux dev box): import-test with
  `python -c "import ast; ast.parse(open('main.py', encoding='utf-8').read())"`
  and unit-test pure functions (`build_rag_prompt`, `make_replacements`, `filter_references`, config load).
- Importing `main` executes the module-level config load, so `config.yaml` must exist even just to import (copy from `config.example.yaml` if missing). Module-level load is the ONLY module-level side effect — everything else (tray, hotkey, llama, uvicorn) lives inside `main()`. Keep it that way.
- RAG requires `chromadb` + `sentence-transformers` (downloads `intfloat/multilingual-e5-small` on first run, ~470 MB).
- The FastAPI app can be exercised without tray/keyboard by importing `app` from `main`.
- Zewnętrzny backend LLM da się przetestować bez płatnego API: postaw lokalny `http.server` odpowiadający OpenAI-compatible JSON-em, ustaw `external.url` na jego adres (z `enabled: true`) i sprawdź `llm_chat_request`/`translate_with_rag`; `main.session` można też podmienić na atrapę, żeby sprawdzić payload, retry na 400 i obsługę `finish_reason`.
- The Settings window can be previewed without the app: `python settings_gui.py` (fake save/restart callbacks). Pure logic worth unit-testing lives in module-level functions: `sync_args_port`, field validation in `SettingsWindow._collect`, `_merge_config_values`/`save_config_values`/`_changed_keys` (main), `_check_prompt_template` (main), `_selection_from_config`/`_initial_selection`/`_memory_label` + `RAGManager.resolve_engines`/`search_selected` (memory selection — stub `RAGManager.__new__` instead of building a real one).
- Real end-to-end (hotkey, tray, llama) is validated by the owner on Windows. Ask for console logs when debugging — the emoji prints trace the full chain.

## API surface (external tools)

- `POST /v1/chat/completions` — OpenAI-compatible response shape, but the translation itself is the hotkey pipeline (`translate_with_rag`): client prompts are ignored, only the `[SOURCE]` section of the text after `\n[USER_PROMPT]\n` is translated (fallback: whole remainder, then last user message), with the tray-selected memories and tray direction. `temperature`/`max_tokens`/`rag_memory` are ignored.
- `POST /v1/chat/completions_old` — archive of the original endpoint: client prompts are forwarded to llama-server, and if a user message starts with `\n[USER_PROMPT]\n`, RAG references are injected as a separate `\n[REFERENCES]\n{json}` message before it. Optional `rag_memory` restricts the search to one memory.
- `GET /v1/memories`, `POST /v1/memories/{name}/reload`, `DELETE /v1/memories/{name}` — memory management (also used by the GUI at `GET /`).
- `GET /health` — llama status, loaded memories, tray memory selection (`selected_memories`; `null` = all), hotkey state, active backend (`llm_backend`: `local`/`external`, `llm_model` in external mode; the external API is never probed — that would cost a request).
- No authentication and permissive CORS; default `server.host` is `0.0.0.0`, so treat every endpoint as reachable from the LAN — don't add anything here you wouldn't expose to the local network.
- There is no internal translation HTTP endpoint — the hotkey path calls `translate_with_rag()` directly. Do not reintroduce an internal-HTTP hop.
